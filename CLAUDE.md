## Commands

```bash
pnpm dev          # Start Next.js dev server (localhost:3000)
pnpm build        # Production build (runs type-check + lint first)
pnpm test         # Vitest unit + integration tests
pnpm test:e2e     # Playwright e2e tests
pnpm test:watch   # Vitest watch mode (dev loop)
pnpm lint         # ESLint
pnpm typecheck    # tsc --noEmit (no emit, just type errors)
pnpm db:migrate   # Apply pending Prisma migrations
pnpm db:seed      # Seed dev database (cities, guide stubs)
pnpm db:studio    # Open Prisma Studio at localhost:5555
pnpm db:reset     # Drop + re-migrate + re-seed (dev only, destructive)
```

All commands are in `package.json`. Do not run `npm` or `yarn` — this project uses `pnpm`.

## Workflow

1. `pnpm test` — run tests first. All green before you change anything.
2. Read `TODO.md` — find the next unchecked task in the current phase.
3. Read `docs/spec.md` for the feature you're about to implement.
4. Write the **failing test first** in `tests/unit/` or `tests/integration/`.
5. Implement in `src/` until tests pass.
6. `pnpm lint && pnpm typecheck` — fix any errors.
7. Commit: `git commit -m "feat: <what> — <why>"`.
8. Update this file or `AGENTS.md` if you learned a non-obvious convention.

## Non-Obvious Conventions

### Next.js App Router
- All `page.tsx` files are **server components by default**. Add `"use client"` only when you need hooks or browser APIs.
- API routes live at `src/app/api/[route]/route.ts` — export `GET`, `POST`, etc. as named exports.
- Server Actions are preferred over client-side fetch for mutations when possible.

### Prisma
- Import from `src/lib/prisma.ts` (singleton) — never `new PrismaClient()` inline.
- Always use `prisma.$transaction()` for multi-step writes.
- Migrations go in `prisma/migrations/` — never edit them by hand after applying.

### Auth
- Session is JWT-based (`strategy: "jwt"` in `src/lib/auth.ts`) — required for edge runtime compatibility.
- Protected API routes must call `getServerSession(authOptions)` at the top and return 401 if null.
- Never trust `session.user.id` from the client — always re-fetch from DB using `session.user.email`.

### TypeScript
- No `any` — ever. Use `unknown` and narrow it.
- API request bodies must be validated with Zod before use. Schema lives in `src/lib/validations/`.
- Shared DB types are generated by Prisma — do not duplicate them in `src/types/`.

### Testing
- Unit tests use `vitest` with `@testing-library/react` for component tests.
- Integration tests use a separate test database: set `DATABASE_URL` in `.env.test`.
- Never test Prisma directly — test the API route or service function that wraps it.
- E2e tests use `playwright` — run against `localhost:3000` (start dev server first).

### Styling
- Tailwind only — no inline `style` props, no CSS modules except for complex animations.
- Use `cn()` from `src/lib/utils.ts` (clsx + tailwind-merge) for conditional class names.
- Dark mode via `next-themes` — use `dark:` variants, never hardcode colors.

## Environment Variables

See `.env.example` for all required keys. Minimum to run locally:
- `DATABASE_URL` — Postgres connection string
- `NEXTAUTH_SECRET` — random 32-char string (`openssl rand -base64 32`)
- `NEXTAUTH_URL` — `http://localhost:3000`
- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — for Google OAuth

## What Claude Should NOT Do

- Do not refactor working code unless explicitly asked.
- Do not remove or skip existing tests — fix them if they break.
- Do not add new dependencies without checking `package.json` first — there may already be a utility for what you need.
- Do not use `any` types.
- Do not write to the DB in tests — use mocks or a test DB with `db:reset` between test runs.
